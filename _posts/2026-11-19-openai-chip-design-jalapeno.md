## 先说结论

这篇比 OpenAI 八月的 Jalapeño 公告有料得多——因为它第一次给出了**可比较的数字**、**可复现的评测方法**，以及一段**自己承认评测可能有水分的话**。

三件事值得记：

1. **Jalapeño 上，模型提出的改动让 vector 单元的标准单元面积降了约 13%、matrix 单元降了约 10%**，并在硅片 bring-up 时被验证。
2. **AMD 旗舰 GPU IP 上最高 14% 的 PPA 改善**（相对"已经高度优化的基线"），部分改动**已经进了送去制造的版图**；下一代旗舰 CPU 的关键模块也验证到个位数的 PPA 提升。OpenAI 的说法是「不到 5 个月拿到大约一年的进展」。
3. **和 Synopsys 签了多年期合作，要训练 GPT-Synopsys**——让模型像资深工程师那样**直接操作 EDA 工具**，目标覆盖 PPA 优化到 timing 与 verification closure。

第三件事的分量，比前两件加起来还大。

## Jalapeño：13% 和 10% 到底动了什么

时间线是 **2025 年初从 GPT‑o3 mini 开始**参与 Jalapeño 设计的。文章把改进拆到了具体电路：

**Vector 单元**（并行的算术与逻辑）——收益来自浮点加法器、乘法器、转换函数、reduction 逻辑和特殊函数单元（SFU）。模型做了两件事：探索**替代的逻辑实现**，以及**重新划分流水线级**（把计算分摊到不同 stage），从而共享硬件、减少中间存储。

**Matrix 单元**——收益累积在浮点加法器、乘法器和低精度点积电路上：
- 一个乘法器重构，综合后**单元面积少约 15%**，延迟从 2 个时钟周期降到 1 个；
- 一个加法器重构，**面积少约 15%**，保持 2 周期延迟；
- 点积逻辑与流水线组织的进一步调整带来额外收益。

**这两个数字要放在正确的坐标系里读。** 是 **standard-cell area**，在**综合（synthesis）阶段**度量，不是最终 die area，也不是 PPA 里的"P"。真正的 die 面积还取决于布线拥塞、利用率、时序收敛时的 buffer 插入与 upsizing——综合里省下的 15% 单元面积，到 P&R 之后常常被吃掉一半。所以 13%/10% 是**方向正确的信号**，不是"芯片小了一圈"。

但"**silicon proven during bring-up**"这句是硬的：这些改动真的进了硅，芯片回来了、能跑。这比任何 benchmark 都有说服力。

## AMD：14% 和"一年压缩到五个月"

这一段的信息量最大，也最需要追问。

**做了什么**：模型**重写 SystemVerilog RTL**——不是给建议，是直接改写描述电路行为的代码，覆盖计算、控制与数据搬运三类电路。然后用 **Synopsys 工具验证每次重写行为等价**，并评估 PPA 权衡。

**结果**：旗舰 GPU IP 上最高 **14% PPA 改善**（相对已经高度优化的基线）；部分改动**已包含在 AMD 最近送去制造的某版设计里**，另一些进了未来版本的生产文件；下一代旗舰 CPU 关键模块验证到**个位数百分比**的 PPA 收益。

**"大约一年的进展在不到 5 个月里拿到"——这句话要打折听。**

- **基线是什么？** "heavily optimized baseline"是个好听的词，但没说这个基线是几轮迭代后、由多少人、在什么约束下得到的。
- **哪个指标？** 14% 是面积、功耗、频率，还是某个加权？对 GPU IP，14% 的功耗和 14% 的面积是两个完全不同的故事，商业含义差一个量级。
- **代价呢？** 每一条 RTL 改动都要跑等价性检查、回归、时序重收敛。如果模型提了 200 个改动、其中 30 个有效，把验证成本算进去，净收益是多少？文章没给。
- **"一年进展"是相对摩尔式的常规优化速度**。这句话在营销上很漂亮，在工程上意味着：这条曲线的斜率被改变了多少，取决于你原来有多少人在这条曲线上工作。

真正值得注意的是那个**流程形态**：模型提改动 → **用 EDA 工具验证等价性** → 评估 PPA → 人工复核。模型的角色不是"替代设计者"，是**在一个已有的、可信的验证闭环里做提案者**。这个形态如果成立，它的瓶颈就落在验证吞吐上——恰好是后端最贵的地方。

## RISC-V 评测：最有价值的部分是那段自我批评

OpenAI 用两个开源 32 位核做了可复现的评测：**PicoRV32**（FPGA 用的紧凑核）和 **OpenTitan 里的 Ibex**（安全芯片的嵌入式处理器）。

**任务一：给原始 HDL，要求提高吞吐。** 度量方式是 IPC（在**对模型隐藏的工作负载**上测）乘以 Yosys 估计的最高频率——也就是每秒指令数。规则很硬：**跑不过检查、或面积超过原始核 16 倍的，直接记 0 分**。每次 run 的预算约 11.2 万 token。

结果：**GPT‑6.2 Astra 在两个核上平均分最高**；在 PicoRV32 上，11.2 万 token 档位的得分约为 GPT‑6 Astra 的**两倍**。

**任务二：从规格书设计一个核。** 只给书面需求和接口模板，让模型自己决定数据通路与流水级划分。全部评测共 **9,881 次计分 run**。

结果很有意思：**五个模型在"从规格设计"时的得分，全都高于"改造现有 RTL"**。

然后 OpenAI 自己给了一记很实在的补刀（原文）：从书面需求出发，模型**可以省掉原核里的一些特性**（比如性能计数器、额外的指令），这些特性对测试吞吐可能没什么帮助——**这可能是得分优势的一部分原因**；要更接近生产级设计，应该**强制要求这些特性、收紧面积上限、并在物理综合后检查时序**。

**这段话含金量最高。** 它承认了三件事：评测的激励是可被"偷工"的；综合前的面积与时序不是最终答案；物理综合之后才是真的战场。任何做过 tape-out 的人读到"post-physical-synthesis timing"这几个字，都知道那意味着什么——那是另一套完全不同的难度。

## 真正的大事：GPT-Synopsys

前面都是展示，这一条是**结构性变化**。

Synopsys 与 OpenAI 签了**多年期协议**，成为"preferred partners"，共同开发 **GPT-Synopsys**：一个专门针对芯片设计、**被优化成会使用 Synopsys EDA 工具**的模型。条款里有几条是硬信息：

- **OpenAI 要 license Synopsys 的 EDA 工具**，用于训练这个专用模型；
- **收入分成 + 联合 GTM**，共同向全球客户销售；
- 模型**跑在 OpenAI 托管的基础设施上**，设计上要能对接客户自己的 agent harness，并深度集成 **Synopsys.ai** 与 **Synopsys Autopilot**；
- 已经在和"领先的半导体客户"做早期技术合作。

新闻稿把演进路径说得很清楚：现在是「通用模型 + agent 连接 EDA 工具跑流程」，**下一步是让前沿模型成为 EDA 工具的专家用户**——学会跑工具、**解释工具的输出**、用工具迭代优化。工程师下单的是**目标**（PPA 优化、timing 与 verification closure），agent 负责跑工具、读结果、改设计、迭代到"已验证"再交人复核。

Ghazi 的话点到了要害：**加速的同时不能牺牲 PPA 和 first-time-right silicon**。这句话同时是承诺和防御——因为投资人会问"AI 会不会把 EDA 变成白菜价"，答案是"不会，因为 ground truth 在工具里，而工具在我手里"。

顺带说一句：这件事让**EDA 三大家变成 AI 军备竞赛的一方**。我在六月的[《Cadence 的 ChipStack》](/posts/cadence-chipstack-agent/)里写过类似的判断，现在 Synopsys 直接跟模型厂签独家式的多年协议——路线不同，但都指向同一件事：**谁掌握工具与流程的 ground truth，谁就掌握 agent 的训练环境。**

## 对做后端的人，这意味着什么

**1. 探索会先被自动化，收口不会。**

模型在这篇里的所有成绩，本质都是**设计空间搜索**：试不同的逻辑实现、试不同的流水级划分、试不同的 RTL 写法。搜索的好处是**并行且便宜，错了只损失一次 run**。

而 floorplan、PDN、CTS、时序收敛、IR/EM、多 corner signoff，特点是**反馈环昂贵、错误代价是 respin**。这两类工作在经济学上完全不同，自动化的顺序也就不同。所以短期内，PD 的核心判断力不但不会贬值，反而会因为上游提案变多而**更稀缺**——你要判断的是"这 30 个提案里哪个能收敛"。

**2. 你现在最该建的资产是 harness，不是 prompt。**

模型改 RTL 这件事之所以能在 AMD 落地，前提是**有等价性检查兜底**（文章明确写了用 Synopsys 工具验证行为保持）。这也是为什么"AI 做设计"在大厂先落地、在小团队难落地：差别不在模型，在**你有没有一套跑得动、信得过的验证流水线**。

具体三件：形式等价（Formality/VC Formal 一类）、可自动跑的回归、PPA 度量的自动化（同一套脚本、同一组约束、可比较的输出）。这三件建好，模型提的每一条改动都能在几小时内被证伪或证实；建不好，模型就是个会写漂亮代码但没人敢用的实习生。

**3. 岗位结构会变，但不是"少一半人"。**

最先被压缩的是**人肉探索**——那种"我试试把这级流水拆开看看面积"的工作。这类活过去是 junior 的练手场，现在会被 agent 批量跑掉。留下的是**定义目标、设置约束、判断收敛风险**的人。

这跟我一个月前写[《LLM 做 IC 设计的基准》](/posts/llm-ic-design-benchmarks/)时的判断一致：基准分数涨得最快的地方，恰好是最容易定义奖励的地方；而 tape-out 的奖励函数至今没人能完整写出来。

**4. 对创业公司：门槛升高了，不是降低了。**

以前做 EDA 相关创业，拼的是算法和 GUI。现在如果要训练"会用工具的模型"，你需要**工具授权 + 真实流程数据 + 能验证的客户**。OpenAI 拿的是 Synopsys 的 license 和 AMD 的生产设计——这个门槛，创业公司基本跨不过去。

反过来，**"把 PPA 度量与等价性验证做成流水线"**这类偏工程、偏脏活的机会反而更实在：它是所有 agent 化设计的前提，且不需要模型授权。

## 🪵 一句话

这篇的核心不是"AI 会设计芯片了"，而是"**AI 已经在真实设计里提出可被验证的改动，并且验证这一环仍然由 EDA 工具和人把守**"。

13%、10%、14% 这些数字会继续涨。真正决定谁能用上的，不是模型分数，是**你有没有一条几小时内能证伪一个提案的验证流水线**。这条流水线，才是下一代设计团队的核心资产。
